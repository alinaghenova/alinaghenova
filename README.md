## Подход к проектированию систем

В проектах я веду **«Заметки на полях»** — фиксирую границы MVP, краевые случаи (например, обработку `null`-значений или отменённых заявок) и компромиссы между скоростью запуска и масштабируемостью архитектуры.

### Инсайт из управленческого опыта, который я перенесла в ИТ

За 5 лет работы в федеральной фитнес-сети (от менеджера до и.о. руководителя отдела и работы с управленческой отчётностью в **1С**) я не раз видела, как новые регламенты и отчёты «ломаются» на уровне линейных сотрудников: когда система требует лишних ручных действий, люди начинают обходить её в таблицах или терять заявки клиентов.

Когда я перешла в системный анализ, этот опыт стал моим главным фильтром при проектировании:
1. **Сначала процесс, потом автоматизация.** Прежде чем рисовать экраны или эндпоинты, важно убрать узкие места в бизнес-процессе (как в кейсе клиники «Вита», где перевод записи в приложение полностью разгрузил администраторов).
2. **Краевые случаи важнее «идеального пути».** Разработчикам нужны не общие пожелания, а точные правила: что делать, если рейтинг равен `null`, слот уже занят или внешний сервис не отвечает.
3. **Ускорение рутины через ИИ.** Использую LLM для валидации XSD/YAML-контрактов, проверки граничных условий и структурирования приёмочных критериев (Gherkin).


### Ключевые принципы:
1. **Бизнес-логика первичнее кода.** Решение конкретных операционных задач.
2. **Контракты и данные без двусмысленности.** Четкие схемы и нормализованные базы данных.
3. **Ускорение рутины через ИИ.** Применение LLM (ChatGPT, Claude) для проверки SQL-запросов и декомпозиции требований.

## Проекты

### 1. [ИТ-платформа автоматизации «Умный дом» (Stets Home)](https://github.com/alinaghenova/stets-home-project)
*User Stories (Gherkin), ERD (3НФ), DFD, Figma, ПМИ* — проектирование MVP с нуля для управления умным освещением и режимом энергосбережения.
- Спроектировала функциональные требования (27 User Stories по Gherkin) и собрала 16 экранов интерактивного прототипа в Figma.
- Нормализовала архитектуру БД до 3НФ (11 таблиц, словарь на 40+ атрибутов) и спроектировала контекстную/логическую DFD.
- Подготовила Программу и методику испытаний (ПМИ) на 11 сквозных сценариев, сократив время оценки бэкенда на 40%.

### 2. [Интеграционный модуль и REST API онлайн-кинотеатра «Otium»](https://github.com/alinaghenova/otium-streaming-tasks)
*REST API, Swagger (OpenAPI), JSON, UML Sequence* — постановка задач на разработку и проектирование логики рейтинга кинокритиков и сортировки каталога.
- Проанализировала 3 микросервиса в Swagger и спроектировала изменения для 7 методов REST API (query-параметры `sortBy`, `direction` и расширение JSON-ответов).
- Отрисовала UML Sequence-диаграмму на 6 участников с опциональными блоками (`opt`) и зафиксировала правило вывода `null`-рейтингов в конец выдачи.
- Сократила время на согласования (Back-and-Forth) с разработчиками на 50% и обеспечила прозрачную оценку спринта.

### 3. [Мобильное приложение и реинжиниринг процессов сети клиник «Вита»](https://github.com/alinaghenova/vita-clinic-modeling)
*BPMN 2.0 (AS-IS / TO-BE), UML State Machine, DFD, User Stories, Figma* — цифровизация записи на приём, лабораторных анализов и электронных назначений.
- Провела реинжиниринг процесса записи (TO-BE в BPMN 2.0), исключив роль администратора (сокращение с 3 до 2 ролей) и внедрив автоуведомления по таймеру за 24 часа.
- Описала жизненный цикл заявки в UML State Machine (6 статусов), потоки данных DFD (хранилища `D1`–`D6`) и собрала 21 экран в Figma/Draw.io.
- Сократила время записи пациента на приём на 25% и автоматизировала выдачу PDF-результатов анализов.

### 4. [Микросервисная архитектура (C4) и REST API сервиса страхования LUCKY](https://github.com/alinaghenova/lucky-insurance-api)
*C4 Container Diagram, REST API, OpenAPI 3.0 (YAML), Swagger, Kafka, RabbitMQ, MongoDB* — проектирование архитектуры нового страхового продукта для домашних животных.
- Интегрировала новый микросервис `Insurance` с базой MongoDB (паттерн Database per service) в контур из 7 микросервисов и 4 внешних систем (`PAY-PAY`, `SHIP-SHIP`, `CRM`, `Amazon S3`).
- Настроила переиспользование корзины (`Shopping cart` через Kafka) и оплаты (`Payment` через RabbitMQ) для запуска MVP с SLA ответа ≤ 10 секунд.
- Разработала спецификацию контракта `GET /insurance` в формате OpenAPI 3.0 (YAML) с UUID-идентификацией, тарифами и кодами ошибок (`400`, `401`, `500`).
