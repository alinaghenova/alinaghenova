### 📁 Избранные технические кейсы в портфолио

#### 1. Интеграционный модуль онлайн-кинотеатра «Otium»
* **Что сделано:** Спроектировала REST API контракты (JSON/XML) и актуализировала XML-схемы запроса и ответа (XSD) для сквозной логики гибкой сортировки и динамической фильтрации каталога контента.
* **Технический вызов и решение:** Для точечной оптимизации запросов к бэкенду и разгрузки систем описала межсервисные потоки данных между Web Server и микросервисами Films/Series с помощью UML Sequence-диаграмм с opt-фрагментами. Протестировала API в Swagger и составила постановку задачи на разработку новых query-параметров, что позволило команде сократить время интеграции и отладки.

#### 2. Платформа автоматизации жилых пространств «Умный дом» (Дипломный проект)
* **Что сделано:** Спроектировала MVP-версию платформы на 27 пользовательских историй (User Stories) с критериями приемки по синтаксису Given-When-Then (Gherkin). Разработала двухуровневые диаграммы потоков данных (DFD), UI-флоу в Figma и программу и методику испытаний (ПМИ) по стандартам ГОСТ 19 и ГОСТ 34 на 28 тест-кейсов.
* **Технический вызов и решение:** Устройства от разных вендоров передавали телеметрию и статусы в разнородных форматах. Для устранения конфликтов я спроектировала логическую ER-диаграмму реляционной БД на 11 таблиц в 3НФ и составила подробный словарь данных на 40+ атрибутов с описанием типов и бизнес-ограничений. Это исключило хаос в архитектуре и минимизировало количество доработок на этапе интеграции оборудования.

#### 3. Мобильное приложение медицинской сети «Вита»
* **Что сделано:** Провела предпроектный анализ предметной области и выстроила карту пользовательских историй (User Story Mapping) для приоритизации бэклога в рамках методологии Agile/Scrum.
* **Технический вызов и решение:** Процесс записи на диагностику содержал много ручных шагов. Я оптимизировала сквозной бизнес-процесс по модели TO-BE в нотации BPMN 2.0, полностью исключив ручное участие администраторов. Разработала диаграммы состояний талонов (UML State Machine), DFD-диаграммы и более 18 wireframe-экранов в Figma, что сократило время оформления заявки клиентом и свело к нулю ошибки ручного ввода данных.

#### 4. Спецификации требований и API для e-commerce и страховых сервисов (Chatty, «Накарабине», Lucky Insurance)
* **Что сделано:** Разработала спецификации требований к ПО (SRS из 7 разделов) с описанием функциональных и нефункциональных требований (производительность, доступность 99,9%, безопасность), бизнес-правил и более 11 вариантов использования (Use Cases) с альтернативными сценариями.
* **Технический вызов и решение:** Требовалось обеспечить независимую работу фронтенд- и бэкенд-команд на этапе проектирования. Формализовала контракт REST API в стандарте OpenAPI 3.0.0 (Swagger) с подробным описанием DTO-схем ответов ($ref, UUID) и семантики кодов ошибок (200, 400, 401, 500) для параллельной разработки и mock-тестирования.
